### Decision

**Winner: Proposal 2 (Layer-4 Hardware First) — `weapon2` GearSlot + `'@classCharge'`/`'@classWindow'` sentinel, one class ledger, no swap verb, zero-stat secondary — with two mandatory grafts from Proposal 1: per-skill weapon-module routing at the cast path, and a fixed per-pair import whitelist.** P2 scored highest with judges (feasibility 8 / degenerate 8, only proposal with no near-fatal), is the only design whose Phase-F multiclass story changes exactly one input (the weapon-access set), and its blast radius on the five green kit gates is provably zero via byte-identical parity goldens since sim/kitFixture.ts equips mainhand only. P1's dual-ledger + Spark/Echo links are deferred to Phase F Layer 2 (its gates were fixture-blind to the 4-slot production bar and never isolated link value); P0 is dropped as the main design (superseded seed; its injection spec near-fatal, 2-4x blind-share miscalc, and Bone Ward Q7 leak all confirmed) but its "measure inertness with tolerance bands, never assert it" gate discipline is kept.

### Rationale

**Why P2 won:** it is the only proposal that fixes a bug that exists TODAY (COMBO_STATE_CREATORS hardcodes 'momentum' to dagger skills at combo.ts:153 while dagger is a §4.2 default weapon for Assassin, WD, AND Hunter), directly answers the dimension ("toward multiclassing" — Phase F needs only getWeaponAccess([primary,secondary])), keeps ONE ledger so StateChips/legibility are unchanged, and its no-swap-verb + zero-stat rules structurally kill the offline-divergence and stat-inflation degenerate cases. Its degenerate judge found zero fatal flaws — unique among the three.

**Grafted from P1 (runner-up):** (1) Per-skill module routing — I verified this is not optional for P2: tick.ts:198 picks ONE module from mainhand.weaponType, comboConsumePreRoll/comboCreatePostCast are called inside modules (dagger.ts:53/260, dataDriven.ts:50/73), and dagger_viper_strike's DoT is interpreted by dagger-module rawBehaviors (dagger.ts:87-88 viperStrikePotency) — so WD staff-primary casting imported dagger skills through the staff module silently loses behavior. P2's plan omitted this entirely; both its judges missed it; P1's feasibility judge proved the routing is safe (tables are skill-id keyed, rawBehaviors id-match so cross-contamination is impossible).
