> Produced 2026-07-12 by a 4-designer + 2-judge design sprint (workflow wf_6eca309f).

>
> Implementation waves (each ships talent-bot green):
>   Wave 1  conditions down-payment + 4 zero-engine keystones
>   Wave 2  IR core (on/mod/rule kinds, normalize, dispatch)      → GATE 1: 310 checks green, normalization ON
>   Wave 3  StateDef registry + Pass-0 validation + 2 uniques      → GATE 2: unique de-inlined

======= ADVERSARIAL VERDICT =======
MERGE, with one design-breaking correction: adopt ir-inventory's schema (rule/mod/grant + ScopedMod + StateDef) as the canonical IR, ir-authoring's Pass-0 registry-closure validation and defaults discipline as the safety layer, and gambit-combat's RotationPolicy as the v1 combat deliverable; demote spec-verbs to a content backlog whose top-10 zero-engine keystones ship FIRST. The correction that reshapes scope: the entire graphMod/rawBehaviors layer is verified DEAD CODE (getSkillGraphModifier is a permanent `return null` stub at src/engine/skills/resolution.ts:85-90; skillGraph.ts has only `import type` consumers), so the ~90 staff rawBehaviors keys, dagger's comboModification overrides, and the ~21-value TriggerCondition union are not hard consumers to express — they are a design quarry to mine and dead reads to delete. This removes roughly a third of ir-inventory's claimed migration surface and converts the scariest v1 line-item (staff migration) into a v2+ content-resurrection task.

--- DECISIONS ---
* CUT the rawBehaviors migration (all ~90 staff keys) from Phase 2 entirely: staff.ts:137 routes through the permanent null stub getSkillGraphModifier (resolution.ts:85-90), so every rb/drb/lrb/hrb/fetishRb read is dead code — DELETE those reads and the dead graphMod call sites (tick.ts:509,1335; zoneAttack.ts:265,426; dagger.ts:442-461 overrides) in a mechanical cleanup commit, and treat _archive/skillGraphs as a design quarry for future staff content authored directly in the IR.
* CUT SkillModifier/ConditionalModifier/TriggerCondition (skills.ts:412-587) as a 'third language to freeze' — it is already dead at runtime; remove the types with the dead reads rather than freezing them (freezing is what produced zombie layer #2). Correct ir-inventory's OPEN-question claim that it is 'still live'.
* KEEP ir-inventory's schema as the canonical IR: three new kinds `rule`/`mod`/`grant` appended to the existing TalentEffect union, ScopedMod with ModScope {damageBucket, element, skillTag, skillId, vsTag, stateId} (root-cause fix for the verified approximation comments at effects.ts:66/101/111), Value = number | number[] rank arrays reproducing scaleTalentEffectByRank math, the `stateChange` trigger subsuming procOnConvergenceCast/BulwarkConsume/ResonanceChargeGain, and normalizeTalentEffect as a total function with zero hand-edits to the 166 NODE_EFFECTS entries.
* KEEP ir-authoring's validation layer verbatim: bot Pass 0 registry closure (every stat/state/trap/minion/skill/buff id from every source must resolve or the build fails), reportUnknownStat replacing the silent no-op at dispatcher:311-314/318-320 (throw in dev/sim, log-once in prod), the `pending` wrapper for forward-compat seeds like maxPoisonStacks, defaults discipline (chance→100, duration→StateDef default, target→StateDef side), and deletion of the two tag-map copies in talent-bot.ts:165/:258-261.
* KEEP unified STATE_DEFS merging COMBO_STATE_SPECS + TALENT_BUFF_REGISTRY + TALENT_TAG_TO_DEBUFF with legacyDebuffId bridging, including keyed stacks (resonance), hysteresis while{enter,exit} (frenzied), and de-phantoming guarded/primed/saturated/contagion_surge at their current inline values (register first, redesign later); save risk is LOW because comboStates/activeTraps/activeMinions are verified ephemeral (state.ts:153-159) — only the scalar crit/resonance/frenzied fields and bulwark tempBuff need a one-shot v74/v75 migrate-on-load, NO dual-read window.
* CHANGE consume-payoff ownership: per-skill payoffs (shadow_mark's 9-skill map, combo.ts:51-61) live as effects on the CONSUMING skill, not on StateDef.consumedBy, because skills already own their tags/costs and Pass 0 validates the stateId reference either way; StateDef keeps only gain rules, duration, mods, and carrier-death.
* KEEP gambit-combat's RotationPolicy design intact: Condition grammar extracted from the while* kinds (one predicate language for talents AND gambits — the refactor of applyConditionalTalentEffects onto evalCondition with 310 checks green is the IR down-payment), first-match-wins evaluation at the verified single consumption point tick.ts:442, slotOrderPolicy as the implicit default with a v74 nullable backfill, 2→8 rule slots via grantRotationRules, CastTrace ring buffer, and per-class curated condition dropdowns.
* CHANGE gambit v1 to include a flat `all` combinator capped at 2 clauses (Berserker bank-and-burst is the launch showcase and needs it; evaluator cost trivial); everything else in the combinator space stays v2.
* KEEP the sim A/B go/no-go gate as a HARD ordering constraint: run default-policy-vs-slot-order per class in the sim BEFORE building RotationPanel UI; if the delta is under ~10% clear speed, buff consume payoffs first — the system's risk is balance decoration, not UI fiddliness.
* CHANGE Pass 6 golden traces to fixture-only: assert exact cast sequences on synthetic fixture builds, assert only DPS-delta direction on real class defaults, so balance retunes don't shatter goldens.
* KEEP normalization semantics-preserving: legacy whileTag normalizes to current global-front-target behavior (talent-bot goldens byte-identical); corrected per-hit vsTag scoping is for NEW authoring only, with per-node balance fixes as a later pass. Gate legacy-arm deletion on a golden test asserting legacy-dispatch ≡ normalized-dispatch per kind.
* SHIP spec-verbs' zero-engine keystones IMMEDIATELY (before or parallel to IR work): Precision Reaper, Pyre Bloom, Curse Glutton, Eternal Court, Plague Bearer (needs only a 'plagued' TalentTag + TALENT_TAG_TO_DEBUFF alias) — verified authorable with existing procOnKill/procOnHit/targetTag/refundCooldown/applyTagAll kinds; this rescues the three verb-less paths' worst nodes with pure data commits and de-risks the IR by growing the corpus it must normalize.
* KEEP spec-verbs' mechParam family as a fourth new kind with defaults equal to the current literals (frenzied 0.5/0.75 at tick.ts:712-715; crit cap 5/4s and resonance cap 5/6s at tick.ts:1088-1116) — it is the only proposal that makes King of Ruin-style capstones pure data and it overlaps nothing in the other designs; limit v1 to the ~6 params with verified engine literals.
* CHANGE spec-verbs' counters family: do NOT build a separate counters registry — express counters as self-scoped StateDefs (crit_stack/resonance/soul_stack already have registry entries per comboStates.ts), with procOnCounterCap expressed as stateChange:capReached; retire the four specialized while*/per* kinds via normalization aliases as proposed.
* CHANGE spec-verbs' rotation-steering assumption: castCondition/castPriority (skills.ts:571,582) is dead (null-stub consumer — the execute-lock at rotation.ts:125-130 never fires today); all keystone rotation-divergence rides gambit RotationPolicy conditions, and the per-keystone policy-divergence sim assertions target Pass 6 fixtures.
* CUT from spec-verbs' action list: extendFrenzied (unresolved conflict with the hysteresis StateDef model — a duration extension has no meaning for an HP-threshold state; redesign as a separate OR-able buff state before authoring Undying Wrath), empowerNextAttack, sacrificeMinion, and instantDamage (subsumed by ir-inventory's dealDamage). KEEP advanceCooldowns (unlocks both Shadowdancer's entire Momentum identity and Blademaster's Perfect Rhythm — two paths per primitive) and procOnLethalHit (Reaver's only verb).
* CUT ir-authoring's RuleProbeHarness and the EVENT_WIRING/site-string manifest from v1 — a bespoke test framework for ~5 rules plus a grep-verified manifest that rots; v1 RULES is a plain registry {id, name, text(params), params} validated by Pass 0 id-closure, with rules exercised by ordinary talent-bot proc checks. Revisit the runtime registration handshake only if authored-but-unwired events actually occur.
* CUT the bow/dataDriven.ts weapon module from Phase 2 (the painful cut): it drags the trap-lift out of dagger.ts plus a new WeaponModule; prove item-reachability via uniques and skill-reachability by attaching effects?: TalentEffect[] to one existing dagger/staff skill. * KEEP uniques de-inlining in Phase 2: add effects?: TalentEffect[] to unique defs and migrate the verified 19 inline branches across 10 items (start with Frostbite Loop and Brambleback's Hide per ir-inventory's worked examples; Adder's Fang lands as the first RULES entry with params replacing the boolean at helpers.ts:23).
* CUT gear-affix effects from v1 (roll-range x Value interaction undesigned — uniques prove the item path first) and CUT PAIR_MORPHS content from Phase 2 (schema may be reserved, but the fire→bleed brief does not exist in MULTI_CLASS_PAIRS.md §5 — Arcane Blade is verified as a Resonance-engine identity; morph content waits on reconciled briefs).
* CUT generated-mechanical-text-everywhere from v1: generate text only for the new rule/mod/grant/mechParam kinds (extending talentEffectText.ts), keep existing hand text for legacy entries, and defer the digits-in-flavor lint and displayText replacement; convert the `?? stat` fallback at talentEffectText.ts:29 into a Pass 0 failure now (one line, kills the silent-label class).
* CUT (defer to v2, unchanged from ir-inventory's own list): projectile/skill-shape sim, per-key resonance expiry, snapshot value capture, single-nearby-target selection, ailment-instance splitting, minion lifecycle, ground effects, transform procs, and the `interval` trigger (schema-reserved, no engine support until a consumer exists).

======= SYNTHESIS VERDICT =======
ADOPT-AND-MERGE: ir-inventory supplies the schema backbone (3 new kinds, ScopedMod/ModScope, Value rank-arrays, 31-entry StateDef registry), ir-authoring supplies the RULES registry + Pass-0 closure validation + generated-text discipline + dataDriven weapon module, gambit-combat is adopted essentially verbatim for RotationPolicy (it is the best-anchored of the four), and spec-verbs becomes the content roadmap (its counter/mechParam primitives are folded into keyed StateDefs and rule params rather than shipped as separate systems). Net new type surface: 3 TalentEffect kinds + 1 presence kind (grantRotationRules), ~15 Trigger members, ~25 Condition leaves + 3 combinators, 5 TalentAction additions, 4 registries (STATE_DEFS, RULES, TRAP_DEFS, existing SUMMON_CONFIGS). Six waves, four hard gates, all behavior-preserving until Gate 4.
